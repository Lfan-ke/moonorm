moonorm

An ORM / SQL toolkit for MoonBit — a parameterized, injection-safe query builder, the way SQLAlchemy Core is for Python. Bound values become ? placeholders, never spliced into the SQL string.

$moon add Lfan-ke/moonorm

✶ The contract at a glance

let (sql, params) = select("users")
  .column("id").eq("age", Int(18)).order_by("name", Asc).limit(10).build()
// "SELECT id FROM users WHERE age = ? ORDER BY name ASC LIMIT 10", [Int(18)]

// bound values are ? placeholders + a params list => injection-safe by construction.

§Query builder

select / insert / update / delete builders with WHERE / ORDER BY / LIMIT, rendering (sql, params) - values are always ? placeholders, never spliced in.

enum
enum Value

A bound SQL value. Values are always carried out-of-band as parameters, never interpolated into the SQL string — that is what makes the builder injection-safe. The variants mirror SQLite's dynamic storage classes: Int/Int64 map to INTEGER, Double to REAL, Text to TEXT, Bool binds as 0/1, and Null to NULL. Rows read back from a driver are decoded into the same type.

struct Table

A lightweight table descriptor: a table name plus its known columns. It is the hand-written stand-in for SQLAlchemy's Table(...) metadata object — MoonBit has no reflection, so the schema is declared explicitly rather than introspected. select() turns it into a Select with every column projected.

pub(open) trait Driver

A database backend. A driver turns a (sql, params) pair — exactly what the query builder emits — into either an ExecResult (for INSERT/UPDATE/DELETE/DDL) or a set of Rows (for SELECT). Parameters are bound out-of-band, never spliced into the SQL. This is the faithful equivalent of SQLAlchemy's DBAPI/dialect seam: the builder is dialect-neutral, each backend adapts the wire.

struct
struct Session[D]

An explicit unit-of-work over a Driver. Unlike SQLAlchemy's implicit autoflush and attribute-triggered SQL, every statement here is issued explicitly — the faithful MoonBit equivalent given the absence of attribute interception, exactly as Diesel and GORM also require. Session is generic over the backend, so it carries no dynamic dispatch cost.

§SQLite driver (native)

A real native SQLite backend over the vendored amalgamation - implements Driver, so Session executes actual CREATE / INSERT / SELECT / UPDATE / DELETE.

struct
struct SqliteConn

A live connection to a SQLite database. Open it with SqliteConn::open; it satisfies @moonorm.Driver, so a @moonorm.Session can drive it directly.

fn
fn SqliteConn::open(path : String) -> Result[SqliteConn, @moonorm.SqlError]

Open (or create) the database at path. Use ":memory:" for a private in-memory database. Returns ConnectError if the file cannot be opened.

fn
fn SqliteConn::exec_script( self : SqliteConn, script : String) -> Result[Unit, @moonorm.SqlError]

Run a semicolon-separated script (e.g. a schema DDL block) in one call. Unlike execute, this uses SQLite's multi-statement exec path and binds no parameters. Returns QueryError with SQLite's message on failure.
